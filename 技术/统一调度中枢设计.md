# 统一调度中枢设计

> 配套 [[技术/多Agent协作|多Agent协作 · 开发实现]]。该章节已说明现状：四 Agent 形态不统一，阿文靠大王对话触发、无自动路由。本文给出统一调度中枢的设计与选型，供大王拍板后落地。

---

## 1. 现状与痛点

| Agent | 当前形态 | 入口 | 阿文如何调度 |
|------|----------|------|--------------|
| 阿文（主） | 系统身份 | WorkBuddy 对话 | 自身 |
| 小王（采购） | Python CLI | `D:\报销工作台\03_脚本\xiaowang_agent.py` | 大王对话喊"小王"，阿文转述 |
| 小吴（入库） | Python CLI | `D:\报销工作台\03_脚本\xiaowu_agent.py`（2026-07-06 补骨架） | 同上 |
| 小李（文员） | WorkBuddy 技能 | `xiaoli-voucher` | 技能调用 |
| 影刀复刻 | WorkBuddy 技能 | `yingdao-rpa` | 技能调用 |

**痛点：**

1. **形态分裂**：小王/小吴 是 CLI，小李/影刀 是技能——阿文调度方式不统一。
2. **无自动路由**：阿文收到大王指令后靠"理解"手动转，没有固化的触发规则去唤起对应 Agent。
3. **流转未在系统层固化**：子 Agent 回报格式已有模板（[[AI执行指南/自动化任务输入输出模板|输入输出模板]]）、异常有决策表（[[AI执行指南/异常处理决策表|异常处理决策表]]），但"谁触发谁、怎么传"仍靠人脑。

---

## 2. 目标

1. 统一四 Agent（+影刀）的封装形态，阿文用同一种方式调度。
2. 固化路由规则：采购 → 小王，入库 → 小吴，文员 → 小李，图灵 RPA → 影刀。
3. 标准化：**指令下发 / 结果回报 / 异常回流** 三件套，全部走既有 AI 执行指南。

---

## 3. 选型对比

### A. WorkBuddy 技能（Skill）封装  ⭐ 推荐

- 把小王、小吴各封装成一个 Skill（`xiaowang`、`xiaowu`），小李/影刀已是技能形态。
- 阿文在对话里直接调用对应 Skill 完成调度。
- **优点**：与现有小李/影刀完全一致；Skill 内可固化触发词、职责边界、调用脚本、回报格式；WorkBuddy 原生支持，无需额外运行时。
- **缺点**：需新建 2 个 Skill（小王/小吴）。

### B. WorkBuddy 专家（Expert）封装

- 每个 Agent 做成专家中心里的专家，阿文转发对话。
- **优点**：更"对话式"，贴近"叫名字就干"。
- **缺点**：专家适合长程对话，不适合"执行一个 CLI 任务"；调度不如 Skill 直接调用清晰；需熟悉 expert 机制。

### C. 保持 Python CLI + 调度脚本

- 新建 `orchestrator.py`：解析大王/阿文指令 → 调用对应 Agent CLI。
- **优点**：不动现有 CLI 体系。
- **缺点**：仍是"对话"与"CLI"两个世界，阿文无法在对话里直接唤起，需手动跑脚本。

### D. MCP 多智能体

- 小王文档提到"MCP 多Agent 协同方案调研"。
- **优点**：标准协议，未来可接外部 Agent。
- **缺点**：当前 WorkBuddy 对 MCP Agent 编排支持待确认，实施成本最高。

---

## 4. 推荐方案（A）

1. **新建 `xiaowang` Skill**：封装 `xiaowang_agent.py` 子命令（download-orders / submit-sent-orders / scan-supplier-docs / complete-purchases 等），固化触发词"小王"、职责边界、回报格式。
2. **新建 `xiaowu` Skill**：封装 `xiaowu_agent.py` 子命令（sync-global / inbound / handoff 等），固化触发词"小吴"。
3. **阿文调度逻辑固化**：读 [[技术/多Agent协作|多Agent协作]] 路由表，按任务类型调用对应 Skill。
4. **回报/异常统一**：走 [[AI执行指南/自动化任务输入输出模板|输入输出模板]] 与 [[AI执行指南/异常处理决策表|异常处理决策表]]。
