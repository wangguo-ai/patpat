## 职责

### 1. 接单 / 下单

- 从图灵“全部”下载待下单和待供应商接单数据。
- 调用三表生成脚本整理供应商待发信息。
- 根据供应商微信映射表判断哪些供应商需要发微信，哪些不需要发。
- 给供应商发送微信。
- 对已发送采购单，在待下单页面点击“下单”。
- 如果没有采购员，转派采购员为“王国钦”。

当前已实现边界：
- `D:\报销工作台\03_脚本\xiaowang_agent.py --download-orders` 负责自动登录/进入图灵采购单管理，导出“待下单”和“待供应商接单”，并合并为当天标准采购单文件。
- 实际页面流程：停留在“全部”页，找到“采购状态”筛选框，分别选择“待下单”“待供应商接单”，点击 `搜 索`，再点击 `导 出`。
- `D:\报销工作台\03_脚本\xiaowang_agent.py --submit-pending-orders --dry` 负责从当天标准采购单读取“待下单”采购单号，预览待处理清单。
- `D:\报销工作台\03_脚本\xiaowang_agent.py --submit-pending-orders` 负责进入“待下单”页面，切到“按采购单”，按采购单号搜索并勾选；采购员为空时先转派给“王国钦”，再点击“批量下单”。
- `D:\报销工作台\03_脚本\xiaowang_agent.py --submit-sent-orders` 负责读取三表格式文件中 `待发供应商信息` 的 `发送状态` / `发送时间`；供应商状态为 `已发送` 时，反查 `版料采购单管理` 中该供应商的待下单采购单并执行图灵批量下单。
- 可用 `--order-nos MCG...` 手动指定采购单号；即使本地导出表没有该单，也会进入图灵页面实查。每个采购单搜索前先点 `重 置`，再切 `按采购单`，避免上一个搜索条件残留。

- `D:\报销工作台\03_脚本\xiaowang_agent.py --scan-supplier-docs --dry` 负责扫描 `D:\报销工作台\01_供应商单据`，默认优先调用 `C:\Users\Administrator\Desktop\Umi-OCR.exe`。当前 Umi-OCR exe 命令行未返回识别文本时，记录为 `待Agent识别`，不进入图灵提交。
- 2026-06-27 回货签收批次里，Umi-OCR 没有识别出可直接执行的关键信息；为避免拖节奏，脚本已把 Umi 单图超时降到 8 秒，并支持 `--ocr-engine easyocr` 在已知 Umi 无效的批次里直接跳过 Umi。遇到类似批次时优先人工核对截图/单据与本地采购单，不要长时间等待 OCR。
- `D:\报销工作台\03_脚本\xiaowang_agent.py --complete-purchases --dry` 仅用于读取已识别成功的采购单并预览做表计划。
- 回货签收 / 采购完成阶段，小王优先通过人工核对或脚本生成执行清单，然后更新 `WorkBuddy采购入库任务表.xlsx` 的 `入库明细`；不直接点击图灵采购完成、提交或打印标签。
- `D:\app\自动化流程\版料采购单生成三表.py` 可识别供应商微信映射表中标记“无需发送微信 / 不发微信 / 无需通知 / 跳过发送 / 不用发微信”的供应商。
- 微信发送由影刀负责；小王不直接操作微信，只读取三表中的发送结果，已发送才进入图灵下单。

优化后的接单 / 下单 SOP：
1. 先运行 `python "D:\报销工作台\03_脚本\xiaowang_agent.py" --download-orders`，从图灵“全部”下载 `待下单` 和 `待供应商接单`，并合并为当天标准采购单。
2. 再运行 `C:\Users\Administrator\Desktop\版料采购单生成三表_backup_20260602_162549.bat`，生成当天 `(三表格式).xlsx`，同时同步小吴全局状态表。
3. 由影刀读取三表中的 `待发供应商信息`，发送微信，并把 `发送状态`、`发送时间` 回写到同一张三表。
4. 小王运行 `--submit-sent-orders --dry` 预览，只统计 `发送状态=已发送` 且 `采购状态=待下单` 的供应商对应采购单；`未发送`、待补联系人、待供应商接单不进入下单。
5. 预览无误后运行 `--submit-sent-orders`，进入图灵 `待下单` 页逐单搜索、勾选并点击 `批量下单`；采购员为空时先转派给 `王国钦`。
6. 首轮失败单会自动二次重试一次。若二次仍失败，记录失败采购单号、截图和原因，再由阿文判断是否人工处理。

### 3. 回货签收 / 采购完成

- 查看 `D:\报销工作台\01_供应商单据` 的供应商单据文件。
- 核对供应商单据与采购单号、实际采购数量、实际采购单价。
- 更新 `D:\报销工作台\04_WorkBuddy任务\WorkBuddy采购入库任务表.xlsx` 的 `入库明细`。
- 图灵系统里的“采购完成 / 提交 / 打印标签”由影刀执行，小王不直接操作系统业务按钮。

回货签收执行口径：
1. 先核对供应商单据图片，不直接操作图灵；如果图片没有 `MCG...` 采购单号，按供应商、供应商物料编号、供应商色号/颜色、数量、单价回查本地采购单导出表或图灵页面。
2. 核对完成后，先通过 `larkbridge.bat send --to feishu:<chat_id> --file <utf8文本文件>` 发飞书确认。发送文本必须用 UTF-8 文件，不要直接把多行中文作为 PowerShell 参数传入，避免中文乱码或内容被截断。
3. 飞书消息按“供应商单据 -> 对应采购单号”逐行列出，不发图片；用户确认后生成/更新入库任务表。
4. 做表前先生成执行清单，每条记录必须包含 `采购单号 / 实际采购数量 / 实际采购单价 / 来源单据`。
5. 只把已核对清楚的记录标为 `待执行`：必须能唯一确定 `采购单号 / 实际采购数量 / 实际采购单价 / 来源单据`，并且金额、单位、单价差异已有业务解释。
6. 无法唯一匹配、缺数量/单价、单位不一致需要换算、或供应商单据与图灵采购单号关系不确定的采购单，写入表时标为 `待确认` 并备注原因，先回报阿文。
7. 表格更新完成并回读校验通过后，必须发飞书给阿文同步结果；不能只在本地写表后结束。飞书消息按“供应商单据 -> 对应采购单号”逐行列出，并补充本次写入条数、合计金额、异常/换算说明、是否已写入 WorkBuddy。参考格式：`小王供应商单据对应采购单号`，每行 `供应商 | 单据号/物料 | 对应: MCG...`，末尾写 `合计: X 张采购单，已写入 WorkBuddy / 尚未操作采购完成`。
8. 飞书同步后再交给影刀操作图灵：影刀去 `待收货` / `待供应商接单` 页面搜索采购单，执行采购完成、提交和打印标签。

2026-06-27 回货签收反错复盘与防呆：
- 写入 `WorkBuddy采购入库任务表.xlsx` 前，必须先备份原表；写入后必须用 `openpyxl` 回读目标行，抽查供应商、物料、颜色、色号、数量、单价、任务状态，确认不是 `?` 或乱码。
- 不要把中文内容直接嵌在 PowerShell here-string 后交给 Python 写 Excel；这会在控制台编码异常时把中文永久写成 `?`。需要写中文 Excel 时，优先使用已存在的 UTF-8 `.py` 脚本文件，或让 Python 从 UTF-8 JSON/CSV/Markdown 文件读取数据。
- 读取或写入中文路径时，PowerShell 先用 `Get-Item -LiteralPath ...` 取真实路径并放入环境变量，Python 从 `os.environ` 读取；不要在 Python 命令行字符串里硬编码中文路径。
- `WorkBuddy采购入库任务表.xlsx` 里可能存在预留空白格式行，不能用 `ws.max_row + 1` 追加。追加前必须按关键列查找“第一个真实空行”：入库任务看 `采购单号列表` 列，入库明细看 `采购单号` 列。
- 一张供应商单据可能包含多条颜色明细，`xiaowang_supplier_doc_scan.json` 当前一张图只适合一条记录；多行单据不要硬塞进一条 OCR 结果，应拆成多条 `采购单号 / 数量 / 单价 / 来源单据` 明细。
- 用户已说明旧单不用管时，必须从执行清单中排除，不要继续匹配或写入任务表。
- 宝年丰布业 `BNF2606260249` 这类按公斤开单的供应商单据，需要先换算成米价再写 `实际单价`；2026-06-27 口径是：只有 `23#`、`77#` 两个颜色为 `2米`，其他已确认颜色按 `1米` 执行。
- 供应商单据金额、图灵参考单价、实际入库单价不一致时，不要默认取图灵参考单价；优先按用户确认的供应商单据口径折算，备注清楚换算依据。
- 怡丰布行电子确认单存在“部分物料每米优惠 10 元”的情况，不能只按图灵参考价或单据行面价机械写。2026-06-29 用户修正口径：怡丰 `XS-260626513` 总价应为 90 元，其中 `6-1275#... 52#驼色` 按 20 元/米，`6-1340#... 137#彩蓝` 按 25 元/米，`6-1340#... 156#芥黄` 按 25 元/米，`6-582#... 10#彩蓝` 按 20 元/米。下次遇到怡丰，必须先用供应商单据总价倒核各行实价，必要时按优惠价写入，不能只照参考单价。
- 写表后如果用户反馈看到问号，先承认并检查文件实际内容，不要解释成显示问题；若已写坏，使用备份或 UTF-8 脚本重写受影响行。

2026-07-06 回货签收复盘与新增防呆：
- 怡丰再次出现“行面价合计不等于红字总额”的问题：`XS-260703417` 明细行面价按 35/40 合计会写成 285，但单据红字总额是 205。处理方法：写表前必须先算“供应商单据总额”和“待写入明细合计”，不相等时按总额倒核；本次按每米优惠 10 元修正为 25/30 元米价，怡丰合计 205。
- 宝年丰按公斤开单，采购单按米入库，且同色号可能对应多个 MCG。处理方法：先从采购单取本次米数，再按供应商单据公斤金额/总额分摊到各 MCG；备注必须写明“按公斤金额倒核到采购单米数”。同色号多单时按采购单需求数量拆分，不凭肉眼挑一个单号。
- 同一供应商单据可能跨多张图片或同一单号分两页，例如鑫顺旺 `X0260601` 两张图片合计 27 米、945 元。处理方法：先把同一单号/同一供应商的图片合并核总，再拆成多条 MCG 明细；最终供应商汇总必须等于单据总额。
- 单据单位和采购单位不同或数量不一致时，不能无备注地直接写。例如恒业按公斤、华讯昌达按 KG、天达可能按码，WorkBuddy 写给影刀通常按采购单单位米；必须用供应商总金额倒核成采购单单位单价，并在 `核对备注` 写清楚换算来源。
- 写完后不要只看总行数；必须按供应商汇总回读，至少核对：怡丰、宝年丰、鑫顺旺这类高风险供应商的汇总金额；再检查采购单号无遗漏/无重复、中文无 `?`。若回读发现总额不对，立即二次备份并局部修正，不要等用户反馈。
- 本次漏发飞书提醒用户。以后回货签收流程的完成条件是“WorkBuddy 已写入 + 已回读校验 + 已飞书同步阿文”，三项缺一不可；如果飞书发送失败，要在最终回复里明确说明未发送成功及原因。
